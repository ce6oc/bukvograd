# Озвучка «Буквограда»: как устроена и как перегенерировать

Приложение говорит **предзаписанными аудиоклипами** — нейроголос «Ирина» (Piper TTS),
сгенерированными заранее и встроенными в репозиторий (`audio/`). На устройстве пользователя
никакая модель не работает: только воспроизведение файлов. Системный TTS (`speechSynthesis`)
остался как **запасной путь** — включается автоматически, если клип не найден.

---

## 1. Архитектура

### Именование файлов: имя = хэш текста фразы

Имя каждого клипа — `FNV-1a (32 бита, hex)` **от текста фразы**:

```
«Молодец! Буква а выучена!»  →  fnv1a_hex  →  audio/1a2b3c4d.m4a
```

Манифест «текст → файл» в рантайме не нужен: `speak()` в `index.html` хэширует строку
на лету (функция `hash36`) и запрашивает файл. Файл не найден → консоль-предупреждение
`[speak] нет клипа` → запасной системный синтез той же фразы.

**Критический инвариант:** алгоритм хэша должен быть побитово одинаковым в двух местах:
- `hash36()` в `index.html` (JS: `charCodeAt` = UTF-16 code units);
- `fnv1a_hex()` в `tools/gen_audio.py` (Python: `text.encode('utf-16-le')`, разбор в 16-битные единицы).

Считать по кодовым точкам Python (`ord()`) **нельзя** — строки с эмодзи (подсказки Буквика)
дадут другой хэш: JS разбивает эмодзи на две суррогатные единицы.

### Последовательности вместо комбинаторики

Фразы вида «Это вэ. Ищем а!» (33×33 комбинации в играх) не генерируются каждая отдельно.
`speak()` принимает **строку или массив строк**; массив играется очередью клипов подряд:

```js
head.say(`Это буква Л. Ищем А!`, ['Это лэ.', 'Ищем а'])   // 2 клипа, bubble показывает первый аргумент
```

### Формат аудио

- **mono, 22050 Hz, AAC (`-b:a 48k`), расширение `.m4a`** — задано в `gen_audio.py`
  (`AAC_BITRATE`, аргументы ffmpeg) и жёстко в URL внутри `speak()` (`'.m4a'`).
- Итого: 798 клипов, ~12 МБ.
- Речь чуть замедлена (`LENGTH_SCALE = 1.12` в генераторе) — замена старого `u.rate = .85`.

### Кэширование и офлайн

- `sw.js` кэширует аудио **лениво** — при первом воспроизведении (прекэшировать 798 файлов
  при установке SW слишком долго). После пары сессий онлайн всё работает офлайн.
- SW кэширует **только `ok`/`opaque` ответы** — 404 не должен попадать в кэш никогда,
  иначе битый ответ застревает навсегда (версия кэша: `bukvograd-v2`).
- На первом касании (`pointerdown`, one-shot) играется беззвучный WAV — разблокировка
  `<audio>` для iOS/Android (требование жеста пользователя).

### Запасной синтез

`synthSpeak()` — прежний путь через `speechSynthesis` (`lang ru-RU`, `rate .85`).
Вызывается, только если клипа нет. Устройства без русского системного голоса в этом
случае промолчат, но игра не зависнет (`onEnd` вызывается по таймауту).

## 2. Регенерация всех фраз (тот же голос)

Окружение не хранится в git (`tools/.venv/`, `tools/models/` в `.gitignore`), поэтому на
новой машине — с нуля:

```bash
cd tools
python3 -m venv .venv
./.venv/bin/pip install piper-tts

mkdir -p models
curl -L -o models/irina.onnx      "https://huggingface.co/rhasspy/piper-voices/resolve/main/ru/ru_RU/irina/medium/ru_RU-irina-medium.onnx?download=true"
curl -L -o models/irina.onnx.json "https://huggingface.co/rhasspy/piper-voices/resolve/main/ru/ru_RU/irina/medium/ru_RU-irina-medium.onnx.json?download=true"

./.venv/bin/python gen_audio.py
```

Генератор **инкрементальный**: существующие файлы (совпадает имя = хэш текста) не
пересинтезируются, создаются только недостающие. Список фраз берётся **прямо из
`index.html`** (парсинг `DATA`, `STICKERS`, `PRAISE`, `TIPS` + шаблоны из кода) — так
что после правки текстов в приложении просто запустите генератор ещё раз.

Деплой:

```bash
cd ..
git add audio/ tools/clips-list.json
git commit -m "перегенерация озвучки"
git push          # GitHub Pages пересоберётся сам
```

`tools/clips-list.json` — полный список «текст → файл», побочный продукт генератора.
Используется для проверок; вручную не редактируется.

## 3. Смена голоса (другой голос Piper)

Русские голоса Piper живут в репозитории
[`rhasspy/piper-voices`](https://huggingface.co/rhasspy/piper-voices/tree/main/ru/ru_RU)
(на момент написания: `denis`, `dmitri`, `irina`, `ruslan`; полный актуальный список — в каталоге).

1. Скачайте пару файлов выбранного голоса (`.onnx` + `.onnx.json`) в `tools/models/`
   (URL по образцу выше, путь = `<язык>/<регион>/<имя>/<качество>/<имя-файла>`).
2. В `tools/gen_audio.py` поменяйте `MODEL_PATH` на новый файл.
3. **Обязательно `--force`**: имена файлов зависят только от текста, а не от голоса, —
   без этого флага инкрементальный режим оставит старую озвучку!

   ```bash
   tools/.venv/bin/python tools/gen_audio.py --force
   ```

4. Поднять версию кэша в `sw.js` (`bukvograd-v2` → `v3`), чтобы у уже установленных
   PWA почистился старый кэш с прежними клипами.
5. Закоммитить `audio/` + `sw.js`, запушить.

Скорость речи: `LENGTH_SCALE` (больше = медленнее; 1.0 = как в модели).

## 4. Смена движка генерации (не Piper)

Любой движок подходит, если соблюсти **контракт**:

- **Вход:** список из 798 фраз — `tools/clips-list.json` (поле `text`; это канонический
  инвентарь всего, что приложение произносит).
- **Выход:** файл `audio/<fnv1a_hex(текст)>.m4a` — mono 22050 Hz AAC.
  Хэш считается функцией `fnv1a_hex()` из `gen_audio.py` (её можно импортировать или
  скопировать). Проверить себя против JS:

  ```bash
  node -e "
  function fnv(s){let h=2166136261;for(let i=0;i<s.length;i++){h^=s.charCodeAt(i);h=Math.imul(h,16777619)>>>0}return (h>>>0).toString(16)}
  console.log(fnv('Молодец!'))"
  ```

  Результат обязан совпасть с Python-версией на тех же строках (включая эмодзи).

- **Меняете формат/кодек/расширение** (например, `.ogg` Opus): тогда
  1) поменяйте расширение в URL внутри `speak()` в `index.html`,
  2) удалите старые файлы из `audio/`,
  3) поднимите версию в `sw.js`.

Идеи альтернативных движков (все русскоязычные):

| Движок | Качество | Размер модели | Комментарий |
|---|---|---|---|
| **Piper** (текущий) | хорошее | ~63 МБ | офлайн, быстрый, простой Python-API |
| **Silero v4** | отличное | ~50–90 МБ (ONNX) | русский как основной язык; нужен `onnxruntime` |
| **eSpeak NG** | роботизированное | ~2 МБ | годится для дешёвых прототипов |
| macOS `say` | хорошее | 0 | только для локальной генерации: `say -v Milena -o ф.wav --data-format=LEI16@22050 "текст"` |
| облачный TTS | любое | 0 | батч-обработка `clips-list.json`; следите за лицензией голоса |

После генерации любым движком: прогнать `gen_audio.py` **без** `--force` (он ничего не
будет пересинтезировать, но обновит `clips-list.json` и проверит целостность), закоммитить.

## 5. Чек-лист перед деплоем

1. **Хэш-паритет**: сгенерировать хотя бы одну фразу с эмодзи в обоих реализациях
   (node-команда из §4 vs `fnv1a_hex`) — hex должен совпасть.
2. **Полнота инвентаря**: запустить приложение локально
   (`python3 -m http.server 8000`), открыть консоль и прокликать основные экраны.
   Канарейка `[speak] нет клипа` в консоли = в коде появилась фраза, которой нет в
   инвентаре генератора → дополнить `build_inventory()` и перегенерировать.
3. **Все файлы на месте**: в браузере на локальном сервере:
   ```js
   const list = await (await fetch('/tools/clips-list.json')).json();
   const miss = [];
   for (const it of list) { const r = await fetch('/audio/' + it.file, {method:'HEAD'}); if (!r.ok) miss.push(it.text); }
   console.log(list.length, miss);
   ```
4. Закоммитить `audio/`, запушить, дождаться сборки (`gh api repos/ce6oc/bukvograd/pages/builds/latest`),
   проверить живой сайт: `curl -s -o /dev/null -w '%{http_code}' https://ce6oc.github.io/bukvograd/audio/<какой-нибудь>.m4a`.
